# ADR-0009: Before/After 측정 조건 고정

- 상태: Accepted
- 날짜: 2026-10-20
- 작성: Lead
- 관련: design.md §7

## 배경
Before/After(보너스 10)와 한계·트레이드오프(20)는 수치가 있어야 설득력이 있다. LLM 출력은 비결정적이고, 모델·날짜·입력이 다르면 비교가 무의미하다.

## 결정
v1 = 10/13 CLI(`eval/v1/run_eval.py`를 원본 폴더에서 실행), v2 = 신규 서버 HTTP API(자동 승인)로 비교한다.
모델은 `openai:gpt-4o-mini`로 고정하고, 테스트셋 10건(`eval/v1/test_cases.json`)을 같은 날 실행하며, 지연은 3회 평균을 쓴다.
지표: 라우팅 정확도, 구조화 출력 성공률, LLM-judge 맥락 점수, Tool 호출 수, 재작성 횟수, 재시작 후 승인 대기 복원, 동시 2요청 총 처리 시간, 1건 평균 지연.

## 대안 비교
| 대안 | 장점 | 단점 | 기각 이유 |
|---|---|---|---|
| ollama로 측정 | 비용 없음 | 소형 모델의 구조화 출력 실패가 비교를 오염, 지연 편차 큼 | 측정 신뢰도 |
| LLM-judge 점수만 | 간단 | 영속화·병행 처리 같은 구조 개선이 드러나지 않음 | 개선 포인트를 못 보여 줌 |
| 테스트셋 확장(30건 이상) | 통계적 신뢰도 | 시간·비용 | design §8 제외 |

## 결과
- 긍정: 기능 후퇴 여부와 구조 개선 효과를 같은 조건에서 보여 줄 수 있다.
- 부정(트레이드오프): 10건이라 통계적 유의성이 약하다. 1건 지연은 MCP·검수 분리로 늘 수 있다(한계로 보고).
- 후속 조치: Day3 오전 Lead가 `eval/run_eval.py`(v2)·`before_after.ipynb`를 작성하고 결과 절을 갱신한다.
- 검증 방법: 노트북 출력 포함 저장, design §7 표에 가설 vs 실측 기록.

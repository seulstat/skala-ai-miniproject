# ADR-0008: 단일 사용자 전제와 MVP 범위 컷

- 상태: Accepted
- 날짜: 2026-10-20
- 작성: Lead
- 관련: design.md §2 "사용자", §8 범위

## 배경
마감까지 2.5일이고, 기능 완성도(30)와 기술 요소(30)를 함께 채워야 한다. 사용자 인증·데이터 분리까지 만들면 E2E 완성이 위험하다.
실제 개인 서류가 외부 LLM으로 전송될 수 있다는 개인정보 문제도 있다.

## 결정
단일 사용자를 전제로 하고(`COACH_DATA_DIR` 하나), design §8의 포함·P1·제외 목록으로 범위를 고정한다.
시연·Git에는 `examples/sample_user`만 쓰고, 실제 데이터가 들어가는 `data/`는 gitignore한다. Day2 오후까지 E2E가 안 되면 P1을 모두 버린다(컷 규칙).

## 대안 비교
| 대안 | 장점 | 단점 | 기각 이유 |
|---|---|---|---|
| 다중 사용자(로그인·사용자별 폴더) | 서비스 완성도 | 인증·세션·데이터 분리 구현, 테스트 증가 | 일정 초과 |
| URL·PDF 공고 변환, 표현집 편집기, 카드 검색·삭제 포함 | 기능 풍부 | 각각 하루 단위 작업 | 핵심 흐름(HITL·Multi-Agent) 완성 우선 |
| 실제 서류로 시연 | 결과 품질이 실감남 | 개인정보 유출 위험 | 개인정보 보호 |

## 결과
- 긍정: 핵심 흐름(준비 → 생성 → 검수 → 승인 → 저장 → 카드)에 집중한다.
- 부정(트레이드오프): 동시에 여러 사용자가 쓸 수 없다. 외부 LLM 사용 시 서류가 전송된다(design §7 한계 4, 완화: ollama 선택지·준비 점검의 개인정보 경고).
- 후속 조치: 범위 컷이 발생하면 Lead가 새 ADR로 기록한다.
- 검증 방법: `check.sh` ④ 금지 파일·개인정보 패턴 검사, CP3 컷 규칙 판정.

# ADR-0020: ollama 모델의 thinking을 끄고, 공고 정리에 규칙 기반 대안을 둔다

- 상태: Accepted
- 날짜: 2026-10-21
- 작성: Lead
- 관련: design.md §5 공고·§7 한계 3, ADR-0012, ADR-0019, agent/llm.py·services/posting.py·services/posting_rules.py·agent/graph.py

## 배경
CP3 브라우저 E2E(사용자)에서 세 가지가 드러났다.
1. 실제 채용 공고("[담당하시게 될 업무를 소개합니다]" 형식)를 붙여 넣으면 공고 정리가 `LLM_OUTPUT_INVALID`로 실패했다. 사용자 평가: "예시 공고만 처리 가능한 수준".
2. 승인 화면에 `REVIEWER_DEGRADED`(AI 검수 생략)가 자주 떴다. 원인 예외는 삼켜져 로그에도 없었다.
3. "오늘 복습할 카드 보여줘"는 오늘 복습일인 카드만 보여 줘서, 방금 저장한 카드가 있어도 "없습니다"로 끝났다.

같은 입력으로 비교했더니 qwen3.5:4b는 기본값(thinking 켜짐)에서 공고 정리 본문이 **빈 문자열, 261초**였고, `reasoning=False`면 **정상 본문, 10초**였다.

## 결정
- `agent/llm.py`: `ollama:` 모델은 `init_chat_model(spec, reasoning=False)`로 만든다.
- 공고 정리: LLM 결과가 비었거나 필수 섹션을 빠뜨리면 규칙 기반 분할(`services/posting_rules.py`: 제목처럼 보이는 짧은 줄의 키워드 → 계약 섹션 이름)로 대신한다. 둘 다 필수 섹션을 못 찾으면 오류 대신 `missing_required`가 있는 초안을 돌려줘 화면에서 사용자가 고친다.
- Reviewer가 강등될 때 원인을 경고 로그로 남긴다.
- 복습 요청에 오늘 대상이 없으면 최근 저장한 카드 5장을 다음 복습일과 함께 보여 준다.

## 대안 비교
| 대안 | 장점 | 단점 | 기각 이유 |
|---|---|---|---|
| thinking 유지 + 시간 제한·토큰 늘리기 | 추론 품질이 오를 수 있음 | 요청당 수 분, 본문이 여전히 빌 수 있음 | 웹 응답 시간으로 쓸 수 없음 |
| 공고 정리를 구조화 출력(섹션별 필드)으로 | 형식 보장 | 소형 모델의 구조화 출력 실패율(ADR-0019)이 그대로 문제 | 같은 실패 지점 |
| 규칙 기반만 사용 | 빠르고 결정적 | 제목이 없는 공고는 못 나눔, 문장 정리 없음 | LLM 정리 품질을 버림 — 대안으로만 둔다 |
| 복습 요청에 키워드로 관련 카드 검색 | 사용자가 기대한 동작에 가장 가까움 | 검색 기준·순위 설계 필요 | 일정상 P1로 미룸, 지금은 최근 카드 표시 |

## 결과
- 긍정: 실제 형식의 공고도 필수 섹션을 찾는다(회귀 테스트 `tests/test_integration_cp3.py`). ollama 응답 시간이 크게 준다. 강등 원인을 추적할 수 있다.
- 부정(트레이드오프): thinking을 끈 만큼 복잡한 판단 품질이 낮아질 수 있다. 규칙 키워드에 없는 제목은 놓친다(사용자가 초안에서 고친다).
- 후속 조치: Day3 측정에서 REVIEWER_DEGRADED·LLM_OUTPUT_INVALID 빈도를 모델별로 기록. 키워드 기반 관련 카드 검색은 P1.
- 검증 방법: `tests/test_integration_cp3.py`, `tests/test_api_docs.py`, 사용자 브라우저 재확인.
